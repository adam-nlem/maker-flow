| [review-feature.md](review-feature.md) | Review workflow (agency upload + client review loop) | `Review` + `ReviewVersion` + `ReviewComment` entities — status lives on `ReviewVersion`, per-version comment thread (cascade remove + orphan removal), Script ↔ Review 1:1 unique. Entity-scoped REST: `GET /api/reviews` (trimmed list, flat array), `GET /api/reviews/{uuid}` (Review + top-level `latestVersion`, **no comments**), `GET /api/review-comments?reviewVersionUuid=&page=&limit=` (paginated top-level comments, replies still nested, newest-first). Responses wrapped in a single `ReviewWithLatestVersionResponseDTO` (combined-groups pattern — same DTO serves list / show / create / update / approve / request-changes / comment-create / comment-update; field selection driven by the entity-level `#[Groups]` + the route-specific group passed via context); `ReviewVersion` + `ReviewComment` shaped via narrowed `#[Groups]` on the entities. Per the project convention every endpoint uses a group named after its own route: `api_reviews_list` / `api_reviews_show` / `api_reviews_create` / `api_reviews_update`, `api_review_versions_approve` / `api_review_versions_request_changes`, `api_review_comments_list` / `api_review_comments_create` / `api_review_comments_update`. The create / update / action groups all expose the same field set as `api_reviews_show`. Agency-scoped on-disk storage (`private/uploads/agency/{agencyUuid}/reviews/{reviewVersionUuid}/{n}.{ext}`), `ReviewVersionController` exposes `/files?reviewVersionUuid=&index=` + `/stream?reviewVersionUuid=&path=` (HLS). Discrete exceptions 33001–33020, PHP upload limits via `php-uploads.ini`, async HLS transcoding (1080/720/480) via `ProcessReviewVideoMessage` + `ReviewVideoStreamingService` (ffmpeg CLI). |
